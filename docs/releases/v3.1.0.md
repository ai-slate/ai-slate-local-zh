# 智匣·融智本地版 v3.1.0

智匣·融智（AI Slate）本地版把多家模型服务商的接入、调度、调用记录、用量与成本查看收进一个可在本机运行的单一程序，并把这些环节连成一条可核对的闭环。你只需下载与系统匹配的一个自包含安装包，校验后即可启动，用浏览器进入安装向导完成初始化；不需要安装 Go、Node、Yarn、Make 或外部数据库。

## 版本定位

`v3.1.0` 是面向正在评估或准备使用本地 AI 模型服务中枢的中文用户、独立开发者与小团队的首个公开本地单机发行版。它在本地单机形态下提供完整的管理页面、API 服务、接入文档和许可证公钥，可变运行数据集中在你指定的运行目录。

## 一个网关，多种模型能力

应用只需要接入一次 `/gateway/llm/v1` 网关。统一的是**网关基址、调用 API Key、模型选择、Provider Key 调度、Invocation 生命周期、用量、计价和文件生命周期**；文本、嵌入、图像、语音/音频及视频在同一套调度、计量与审计体系下管理，但各自使用明确的路径与参数，而不是一个相同请求格式覆盖所有能力。

完整的模型能力表、统一入口边界和最小调用示例见 [项目 README](../../README.md#统一入口支持的模型能力)。

## 包内内容

每个平台包只有一个顶层目录，目录内固定包含八个文件：目标平台的 `slate`（Windows 为 `slate.exe`）、`README.zh-CN.md`、`RELEASE.json`、`SHA256SUMS`、`LICENSE.md`（本软件的专有许可），以及 `start`、`stop`、`upgrade` 三个脚本（Linux/macOS 为 `.sh`，Windows 为 `.cmd`）。包内 `SHA256SUMS` 校验的是除它自身以外的七个文件；`LICENSE.md` 也在完整性校验范围内，使用和转移安装包时请一并保留。

## 快速开始

1. 前往 GitHub Releases（<https://github.com/ai-slate/ai-slate-local-zh/releases>），下载与操作系统和 CPU 架构匹配的平台包，以及根 `SHA256SUMS`。
2. 校验压缩包 SHA-256，解压后进入包内顶层目录，再校验包内除 `SHA256SUMS` 自身外的七个文件：Linux 使用 `sha256sum -c SHA256SUMS`，macOS 使用 `shasum -a 256 -c SHA256SUMS`，Windows 使用 PowerShell 逐文件比对。完整的分平台命令见 [README 的“校验与解压”](../../README.md#校验与解压)。
3. Linux/macOS 执行 `chmod 0755 ./slate ./start.sh ./stop.sh ./upgrade.sh`、`./slate self-check`、`./start.sh`；Windows 执行 `.\slate.exe self-check`、`.\start.cmd`。
4. 打开 <http://127.0.0.1:18084/> 进入安装向导，依次完成：验证许可证、创建管理员、接入模型服务、完成确认。Swagger 文档在 <http://127.0.0.1:18084/swagger/index.html>，接口文档在 <http://127.0.0.1:18084/openapi.json>。
5. 做一次最小真实调用，并在调用记录、用量与分析中核对结果。

## 已知限制

- 本地版是 **SQLite 单机产品**：不支持切换 PostgreSQL，也不支持多个实例共享同一运行目录。
- 不同模态使用各自协议与参数：文本包含 Responses、Chat Completions、Anthropic Messages 三种独立结构，图像、语音、视频各有自己的路径；不提供“一个请求格式覆盖全部能力”的接口。
- 模型能否调用取决于你已配置的服务商、密钥、网络、余额和权限。内置目录条目只是候选，界面显示“已配置”也不代表该模型已通过真实调用验证，实际可用性以一次最小真实调用为准。
- 当前不提供调用前预报价；价格缺失时会明确标记为缺失，不会当作无费用处理。

## 升级适用性

- 升级只替换二进制并重启；数据库、许可证、服务商密钥和本机登录签名材料继续使用原运行目录。
- 必须把新版本解压到**另一个目录**，从新安装包运行 `upgrade`，用 `--target` 指向旧安装中的二进制、`--runtime-dir` 指向原运行目录；不要在旧二进制自身上执行自替换命令。
- 建议先执行 `upgrade --check` 预检；默认不生成业务数据备份，需要时显式增加 `--backup --recipient-file` 或 `--backup --passphrase`。
- 跨 SQLite schema 版本升级必须依据该次发布说明的迁移流程处理，不能假设数据库可逆，也不要手工修改数据库版本。
- 从早期版本升级前请先完成加密备份，并阅读对应版本的迁移说明。完整步骤见 [README 的“升级版本”](../../README.md#升级版本)。
